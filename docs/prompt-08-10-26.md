Tolong bantu saya merefaktor arsitektur backend NestJS dan skema Prisma untuk sistem HRIS. Berdasarkan evaluasi bisnis, kami memutuskan untuk memantapkan struktur data history dan keamanan transaksi pemotongan saldo terlebih dahulu, sementara fitur _auto-generate_ alokasi gaji bulanan ditunda menunggu SOP final dari tim HR.

Berikut adalah tugas perbaikannya:

### 1. Modifikasi Skema Prisma (`schema.prisma`)

- **Pindahkan Gaji ke SK:** Hapus field `gaji_bulanan` dari model `Pegawai`. Tambahkan field `gaji_bulanan Int @default(0)` ke model `Sk` agar riwayat gaji bisa di- _track_ per penugasan/kontrak.
- **Field Default Sumber Dana di SK:** Tambahkan field referensi di model `Sk` untuk menyimpan pengaturan _default_ sumber pendanaan (khusus TA). Tambahkan:
  - `sumber_dana_default SumberDana?`
  - `ro_id_default String? @db.Uuid`
  - `dana_operasional_id_default String? @db.Uuid`

### 2. Implementasi Prisma Transaction (Keamanan Saldo)

- Buat atau perbarui _Service_ pada NestJS untuk pembuatan (`Create`) dan pembatalan (`Cancel`) data di model `AlokasiGajiTA`.
- Wajib menggunakan `prisma.$transaction` agar proses ini berjalan secara atomik:
  1. **Create:** Saat `AlokasiGajiTA` disimpan, sistem harus otomatis melakukan `INSERT` data pengeluaran (debit) ke tabel `RoTransaksi` (jika sumber dana RO) atau `DanaTransaksi` (jika sumber dana Operasional). Secara bersamaan, update saldo yang tersisa di tabel terkait. Jika saldo tidak cukup, batalkan seluruh transaksi (_rollback_).
  2. **Cancel:** Jika `AlokasiGajiTA` diubah statusnya menjadi `DIBATALKAN`, sistem harus otomatis membalik prosesnya dengan melakukan `INSERT` pemasukan (kredit) untuk mengembalikan sisa saldo seperti semula.

### 3. Endpoint Tracking Expiry SK

- Buat sebuah _service_ dan _endpoint_ API (misal: `GET /sk/expiring-soon`) yang bertugas mengembalikan daftar SK yang masa berlakunya hampir habis.
- Logika query: Ambil data `Sk` beserta relasi pegawai dan unit kerjanya, dengan kondisi `status_aktif == AKTIF` dan `tanggal_selesai` berada pada rentang hari ini hingga 30 hari ke depan. Data ini akan digunakan _frontend_ untuk memunculkan notifikasi/alert di _dashboard_.

Tolong berikan output berupa:

1. Kode lengkap update `schema.prisma`.
2. Contoh implementasi kode NestJS (_Service_) yang berisi logika `prisma.$transaction` untuk Alokasi Gaji TA.
3. Contoh implementasi kode NestJS (_Service_) untuk query _expiry_ SK.
